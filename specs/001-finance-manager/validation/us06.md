# US6 — Перевод между своими счетами

Дата: 17.10.2026. Область: Фаза 8, T061–T066, ФТ-023–025,029, КУ-004.

## Реализация

- Strict Zod DTO: два разных активных счёта с явными workspace ids, положительные конечные decimal-строки без exponent, date-only и отдельные описания сторон. Валюта определяется сервером по счёту; scale проверяется без округления ввода. В этой фазе поддерживается одна валюта с равными суммами. Derived rate pair сохраняет обе точные суммы и курс 1 с направлением source_per_destination. FX — отдельная US23.
- Чистый domain использует существующие money primitives с динамической Decimal precision; денежной арифметики в React нет. Новых таблиц, миграций или зависимостей не добавлено.
- Shared financialTransaction блокирует пространства, членство и счета в установленном порядке. Обе legs, action/revision, balance projections, версии счетов, scoped audit и receipt фиксируются одной PostgreSQL-транзакцией. Повтор ключа возвращает разрешённый результат без второго эффекта; иной payload конфликтует; новый ключ разрешает намеренный повтор.
- Для личное ↔ семья проверяются обе стороны и владение личным пространством текущего actor. Семья ↔ семья запрещено. После исключения или soft-delete новые действия и receipt retry запрещены. Scoped DTO, история счетов и audit содержат только собственные legs: противоположный account id, название, баланс и приватное описание не возвращаются.
- Отрицательный остаток требует отдельного подтверждения. Warning откатывает все записи; token связан с actor/payload/scope/account versions. Изменение баланса требует нового подтверждения. Отмена ничего не сохраняет.
- На dynamic странице счетов добавлена форма React Hook Form/Zod с русскими подписями, pending, фокусом ошибки/предупреждения, сохранением ввода и operation key при потере ответа, dirty navigation guard. Server Action проверяет session/права через application service и обновляет страницы обеих сторон. Shared cache финансовых данных не используется.
- Переводы исключены из income/expense queries. Факт бюджета строится в последующей US7 на расходах, отдельного budget service здесь нет. Создание переводов завершено; редактирование/отмена с revisions и соответствующими permission cases запланированы в US21 (Фаза 19), а не в T061–T066.

## Среда и команды

Node 24.22.0, pnpm 12.14.0, PostgreSQL 18.6 в изолированном Compose-проекте finance-phase8-tests, БД finance_test. Тестовый env и SMTP fixture без реальной доставки. Рабочая БД не использовалась. `/tmp/finance-run` выбирает закреплённый toolchain, `/tmp/finance-test-run` дополнительно загружает приватный test env.

```sh
pnpm exec vitest run --project unit tests/unit/transfers.test.ts
pnpm exec vitest run --project integration tests/integration/transfers.test.ts
pnpm test:unit
pnpm test:integration
pnpm exec playwright test tests/e2e/transfers.spec.ts --workers=1
pnpm exec playwright test --workers=1
pnpm typecheck
pnpm lint
pnpm format:check
pnpm build
```

Проверены conservation и большие точные суммы; same-account/unequal/scale/date/FX rejection; чужие/архивные счета и scope spoofing; отсутствие session; конкурентный повтор, intentional duplicate и conflict; immutable pair/rate/audit/version; два встречных перевода; полный rollback после первой leg и обновления debit balance при сбое второй leg; decline/stale/confirm/replay отрицательного остатка; personal↔family в обе стороны; family internal transfer участником; отсутствие личных деталей в семейных DTO/account history/audit; отзыв доступа, deleted family и гонка remove/write. Browser проверяет числовую приёмку, потерю ответа после commit с безопасным повтором, фокус/ошибки, минус, dirty guard и открытую форму после исключения. Скриншот mobile/dark просмотрен: overflow не обнаружен. Это целевая проверка доступности, не полный аудит WCAG.

Начальный unit запуск ожидаемо падал до появления domain. Первый integration запуск блокировал sandbox, следующий показал остановленную тестовую БД; для проверки поднят отдельный контейнер. Sandbox build заблокировал служебный порт Turbopack; кэш с сохранённой ошибкой перенесён в `/private/tmp/finance-phase8-build-0zjjq3ka`, чистый build вне sandbox прошёл. ESLint/TypeScript не потребовали исправлений; Prettier исправил форматирование import. Dev server сообщает destination stream errored при прерывании browser response; финансовый результат и повторы проверены независимо.
