# US9 — Резервный фонд и общие цели

Дата: 17.10.2026. Область: Фаза 10, T073–T078, ФТ-033–039, КУ-006–009.

## Реализация

- Общая модель goal поддерживает ordinary и reserve, описание, необязательную желаемую дату, связанный счёт, архив и version. Reserve settings содержат месячную сумму и положительное целое число месяцев. Число месяцев хранится как целочисленный NUMERIC/string с CHECK, без искусственного продуктового ограничения int32. Связь с будущими обязательствами в P1 недоступна: linked_obligation_id всегда NULL. FK и link/unlink появятся в US14.
- Миграция `us09_reserve.sql`, журнал и Drizzle snapshot. Составной FK workspace/account/currency, partial UNIQUE одной активной цели на счёте, positive ordinary target, finite money, scale по существующему SQL currency helper. Deferred triggers обеспечивают ровно одни settings для reserve и отсутствие settings у ordinary, в том числе после изменения типа. Workspace цели и идентичность settings неизменяемы. Архивация сохраняет настройки, историю и деньги, освобождая связь для новой активной цели.
- Strict Zod input и чистый Decimal domain. Накопления — полный текущий balance projection связанного счёта. Target резерва = monthly amount × months; remaining учитывает отрицательный баланс; percent округлён half-up до двух знаков, coverage до двух знаков без незначащих нулей. Достижение вычисляется при чтении и обратимо; превышение цели/периода не обрезает факт.
- При нулевом обязательстве target/remaining равны нулю, status=no_obligation, percent/coverage/reached=null. Отрицательный баланс отдельно отмечен дефицитом. При положительном обязательстве и отрицательном балансе status=deficit, percent/coverage=null, reached=false, remaining учитывает весь минус. Восстановление положительного платежа возобновляет расчёты по текущему счёту.
- Create/update/archive используют shared financialTransaction, актуальные permissions, workspace/membership/account locks, expectedVersion, scoped audit и receipt. Запись цели/settings/audit/receipt атомарна; деньги и ledger не изменяются. Конкурентное занятие счёта и устаревшая версия конфликтуют. Query выполняется на общем REPEATABLE READ snapshot с текущими счетами; после реального дохода/расхода derived progress меняется без отдельного обновления цели.
- Dynamic/no-store `/w/[workspaceId]/goals`, ordinary/reserve React Hook Form/Zod формы, русские подписи, personal/family context, loading/error/focus, dirty navigation guard, безопасный повтор после потери ответа, явное подтверждение архива. Денежных расчётов в React нет. История накоплений доступна через существующую историю связанного счёта. Новые архивные или занятые счета не предлагаются; существующая связь с архивным счётом сохраняется. Добавлена ссылка из раздела счетов.
