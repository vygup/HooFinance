# US12 — Изменение величины резерва

Дата: 17.10.2026. Область: Фаза 14, T097–T102; ФТ-038–039, КУ-009.

## Реализация

Отдельный strict Zod DTO adjustReserve принимает goalId, monthlyAmount и coverageMonths. Счёт, валюта и остальные поля цели читаются сервером и сохраняются. Масштаб суммы проверяется по сохранённой валюте. Domain переиспользует Decimal goalProgress; новые таблицы и миграции не нужны. Связь с регулярным обязательством относится к последующей US14 и здесь не добавляется.

Application service использует financialTransaction: текущая сессия и членство, workspace/membership locks, receipt, актуальная scoped проекция результата на retry. Repository блокирует активную reserve goal, проверяет expectedVersion и переиспользует persistGoal для атомарного изменения настроек, увеличения goal.version и scoped before/after audit. Счёт, его баланс, версия и история операций не меняются. Ошибка аудита откатывает настройки, версию и receipt.

На dynamic/no-store странице целей подключена отдельная форма настроек с React Hook Form/Zod, русскими подписями, pending/error/focus и защитой несохранённых данных. Operation key сохраняется после потери ответа; повтор с тем же payload безопасен. В React денежной арифметики нет. Существующее полное редактирование цели сохранено.
