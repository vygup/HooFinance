# US8 — Накопительный счёт для ипотечной подушки

Дата: 17.10.2026. Область: Фаза 11, T079–T084, ФТ-015,034–035, КУ-006.

## Реализация

- Переиспользованы существующие account schema/создание счёта US3 и goal schema/commands US9. Накопительный, сберегательный и остальные денежные типы доступны целям. Тип счёта остаётся описательным; ограничения только накопительными счетами спецификация не вводит. Новых таблиц, миграций, денежных остатков или команд записи нет.
- `savings-account-input.ts` и domain определяют strict account UUID selection, безопасный DTO и общую eligibility-функцию. Занятый или архивный счёт не предлагается новой цели; текущая связь доступна при редактировании, в том числе для архивного счёта. Достигнутая активная цель продолжает занимать счёт.
- Goal query использует scoped repository account options с типом, точным балансом и версией. Новая application read query возвращает выбранный счёт и всю действующую историю, включая операции до создания цели, на одном REPEATABLE READ snapshot. Переиспользуется общая account projection, соблюдающая current revisions и privacy. Audit и посторонние account поля не включены в новый DTO.
- Запись связи остаётся в существующем goalCommand с shared financialTransaction, актуальными workspace/membership permissions, locks, expectedVersion, scoped audit и receipt. Partial UNIQUE и серверная проверка запрещают вторую активную ordinary/reserve цель на том же счёте. Привязка не создаёт ledger action, не переписывает opening/balance/history и не добавляет актив второй раз.
- `SavingsAccountPicker` встроен в существующие React Hook Form/Zod формы обычных целей и резервов. Server Action читает сессию и проверяет explicit workspace/account на сервере. Предпросмотр показывает тип, начальный/текущий баланс и историю накоплений; loading, безопасная ошибка, focus и повторная загрузка. Денежных расчётов в React нет; форматирование использует пользовательскую локаль.
- Результаты асинхронного предпросмотра связаны с workspace/account/version и попыткой загрузки; запоздалый ответ прошлого выбора не заменяет текущий. Форма создания сбрасывается при смене workspace. Страницы остаются dynamic/no-store; финансовые данные не помещаются в shared cache.

Unit проверяет накопительный account contract, средства 220000 как один актив, eligibility занятых/архивных/текущих счетов, сохранение pre-goal history/signs и строгий DTO.

PostgreSQL проверяет 203000 opening +20000 income −3000 expense до цели →220000; linking/replay сохраняют полную проекцию счёта неизменной, total равен220000, goal actual равен220000. Вторая ordinary цель после reserve конфликтует. Две конкурентные ordinary цели на одном счёте дают ровно один success и один conflict, без изменения денег/истории. Проверены unauthorized/foreign account/foreign workspace/invalid UUID, zero и подтверждённый negative opening correction; история архивного счёта сохраняется. Полный набор включает прежние проверки rollback, audit/version/idempotency, семейных прав, отзыва доступа и ограничений БД из US9/US3.

Browser создаёт накопительный счёт с200000 и реальный доход20000 до цели; выбранный счёт показывает220000, прежний opening200000 и доход в истории. Искусственно прерванный запрос предпросмотра даёт понятную ошибку и focus; повтор загружает данные. После создания резерва actual220000 и прежняя история сохранены, занятый счёт отсутствует в новой форме цели, общий баланс счетов остаётся220000. Регрессия US9 проверяет edit/zero/restore/archive. Mobile/dark screenshot просмотрен, горизонтального overflow нет. Это целевая проверка интерфейса, не полный аудит WCAG. Полный E2E-набор в этой фазе не запускался.

Первый unit запуск до domain ожидаемо падал. TypeScript обнаружил exact optional prop и неподдерживаемый log code; исправлены. При доработке ключа предпросмотра исправлено оставшееся имя поля error-state. Первый browser запуск попал в циклические HMR reload ещё на регистрации: сервер остановлен, кэш перенесён в `/private/tmp/finance-phase11-cache-mz7zsgyf`, чистый запуск восстановил нормальную работу. Следующий запуск обнаружил ошибку regex-проверки неразрывных пробелов денежной локали; проверка заменена на нормализованный string assertion, продуктовая сумма и история были корректны. Итоговый browser прогон прошёл целиком. Production build выполнен вне sandbox из-за известной потребности Turbopack в служебном локальном порту.
