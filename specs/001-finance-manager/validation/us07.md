# US7 — Месячный бюджет

Дата: 17.10.2026. Область: Фаза 9, T067–T072, ФТ-030–032, КУ-005.

## Реализация

- Monthly budget и category limits хранятся отдельно от ledger. Миграция `us07_monthly-budget.sql`, журнал и Drizzle snapshot добавлены. UNIQUE workspace/month/currency, первый день месяца, положительная версия, finite nonnegative NUMERIC без typmod, составные FK и expense category проверяются PostgreSQL. Currency/scale validator закреплён по каталогу существующего Node 24/Intl; trigger запрещает несовместимый масштаб лимита и изменение идентичности бюджета. Категорию с бюджетными связями нельзя превратить в доходную.
- Strict Zod input отклоняет неизвестную валюту, некорректный месяц, exponent/special values, отрицательные суммы, лишний масштаб и повтор категории. Currency amounts остаются строками, расчёты находятся в чистом domain с динамической Decimal precision.
- Save использует shared financialTransaction: актуальная сессия, блокировка workspace/membership, permissions, expectedVersion, audit, receipt и limits сохраняются атомарно. Создание поверх существующего плана без версии конфликтует; конкурентные изменения не теряются. Audit содержит прежний и новый scoped план. Бюджет не меняет деньги счетов.
- Query читает план, категории и расходы на одном REPEATABLE READ snapshot. Переиспользуется fact query действующих expense legs текущей revision: переводы, начальные остатки и другие месяцы/валюты исключены. Все расходы, включая категории без лимита, входят в общий факт. Категории после переименования/архивации сохраняют связи; существующие архивные лимиты можно редактировать, новые архивные категории не предлагаются.
- Русская dynamic/no-store страница `/w/[workspaceId]/budget`: выбор месяца и валюты, контекст personal/family, план доходов/расходов/остаток, общий факт и остаток, категории, процент и превышения. Отсутствующий бюджет явно отличается от нулевого плана; пустой лимит отличается от нулевого. При нулевом лимите процент отсутствует, превышение сохраняется.
- React Hook Form/Zod, pending/error, focus, dirty navigation guard, безопасный повтор operation key при потере ответа. Денежных расчётов в React нет. Ссылка на бюджет добавлена в раздел счетов. Текущий месяц определяется по личному/семейному часовому поясу существующими helpers.

## Проверки

Среда: Node 24.22.0, pnpm 12.14.0, PostgreSQL 18.6, отдельный существующий контейнер `finance-phase8-tests-db-test-1` и БД `finance_test`. Рабочая БД не использовалась. Unit проверяет 200000−115000=85000; 33000/30000 → −3000/110%; безлимитные расходы, нулевой лимит, пустые данные, разные валюты, большие точные суммы и validation. Первый запуск до реализации ожидаемо падал на отсутствующем domain.

PostgreSQL проверяет save/replay/concurrent duplicate, уникальность бюджета, version conflict и гонку разных изменений, scoped audit, неизменность счетов после сохранения плана; fact включает безлимитные расходы, границы месяца и исключение перевода/начальных остатков; отдельную валюту/месяц; unauthorized/foreign workspace/foreign category/income category, composite FK, invalid money/scale/date; полный rollback plan/limits/receipt при ошибке audit; семейного участника, отзыв доступа к read/replay и запрет writes после soft-delete.

Browser проходит числовой пример с пятью лимитами и реальным расходом, показывает превышение, редактирует план до нулевого лимита и переключает месяц с пустым планом. Обе темы и mobile проверены, screenshot mobile/dark просмотрен: горизонтального overflow нет. Это целевая проверка интерфейса, не полный аудит WCAG. Полный E2E-набор в этой фазе не запускался; unit/integration регрессии пройдены полностью.

Начальное подключение к тестовой БД блокировал sandbox, затем обнаружен остановленный контейнер: он запущен для проверок. Sandbox build запрещал служебный порт Turbopack; кэш с ошибкой перенесён в `/private/tmp/finance-phase9-build-f_2qmjso`, чистая сборка вне sandbox прошла. ESLint потребовал event wrapper для ref-aware submit handler; TypeScript обнаружил необязательное значение в tuple E2E fixture, исправлено `as const`. После исправлений проверки прошли.
