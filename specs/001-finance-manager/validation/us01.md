# Валидация US1 — Регистрация и личное пространство

**Дата:** 17.10.2026. **Область:** Фаза 3, T024–T034; ФТ-001–005, КУ-001 и связанные ограничения ФТ-066. **Результат:** пройдено. Следующие истории не реализовывались.

## Реализация

- Signup Better Auth, включая прямой `/api/auth/sign-up/email`, создаёт пользователя, credential account, сессию, профиль и ровно одно personal workspace в одной PostgreSQL-транзакции. Cookie передаётся браузеру только после успешного завершения. Повторная нормализованная почта и конкурентный signup не создают дублей.
- Пароли, вход, выход и одноразовый часовой reset обслуживает Better Auth. Восстановление возвращает одинаковое подтверждение для существующей и отсутствующей почты; старый пароль после сброса не работает. Прямые auth endpoint limits сохраняются.
- Профиль изменяет только имя, локаль и IANA timezone собственной session; version передаётся строкой. Preferences и имя обновляются атомарно. Stale version возвращает conflict; чужой actor/email и некорректные поля отклоняются.
- `/register`, `/login`, `/forgot-password`, `/reset-password`, `/profile`, `/dashboard` подключены к application services через Server Actions. Профиль не требует выбранного workspace. Личное пространство видно только владельцу; после выхода профиль/дашборд перенаправляют на вход.
- Формы используют React Hook Form и Zod, русские подписи, состояния ожидания, сообщения и focus. Ввод сохраняется при ошибке/конфликте. Навигация с несохранённым вводом предупреждает пользователя; загрузка актуального профиля требует подтверждения. Дата на личном дашборде учитывает сохранённые locale/timezone.
- Auth redirect с пустым body не читается как JSON. Dev-логирование Next.js URL и аргументов Server Actions отключено, чтобы не записывать reset tokens и пароли. Auth JSON по-прежнему исключает session secrets и использует private, no-store.

## Проверенные инварианты и сценарии

1. Ровно одно personal workspace и профиль после signup; повторная почта после trim/case normalization и конкурентная регистрация оставляют одного пользователя и одно пространство.
2. Искусственный сбой после создания personal workspace/profile откатывает регистрацию целиком: нет user, workspace, profile, credential account или session. Foundation regression продолжает проверять tx-aware adapter.
3. Два пользователя в общей семье не получают доступ к personal друг друга. Чтение без session и со старой cookie после signout отклоняется сервером.
4. Профиль обновляет version ровно на один. Повтор с устаревшей версией не меняет имя; из двух конкурентных изменений проходит одно. Попытка указать чужой user id или изменить email отклоняется.
5. Reset для известной/неизвестной почты имеет одинаковый ответ. Проверены одноразовость, часовой срок, expiry, запрет старого пароля и успешный вход с новым. Регрессии foundation проверяют лимиты входа/reset, concurrency и недоверенные proxy headers.
6. В браузере пройдены register → dashboard → profile → logout → login → forgot-password → письмо → reset-password → login. Проверены повторная почта, invalid/expired token и stale profile в двух вкладках, сохранение ввода и отмена перехода с несохранёнными изменениями.
7. Проверены focus при ошибке, отсутствие горизонтального overflow и отображение форм в desktop/light и mobile/dark. Скриншоты профиля обеих тем просмотрены. Это целевые проверки интерфейса, а не заявление о полном независимом аудите WCAG.
8. Auth transport не выдаёт token в DTO и не устанавливает cookie при неуспешном signup. Регрессионный unit-тест сохраняет пустой reset redirect и no-store.
