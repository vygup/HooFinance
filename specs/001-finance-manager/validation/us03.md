# US3 — Создание и архивация счета

Дата: 17.10.2026. Область: Фаза 5, T042–T047; ФТ-015–018 и соответствующая часть КУ-003. Доступен интерфейс `/w/[workspaceId]/accounts`, ссылка из личного дашборда и переключение доступных пространств.

## Реализация

- Один shared `financial_account`, без новых money/account tables и миграций. Шесть типов счёта; ISO currency catalog; opening/balance передаются точными строками. Domain использует Decimal/shared money primitives, не React/DB/number arithmetic. Строгие Zod DTO запрещают смену currency/workspace и неизвестные поля. Описательные данные редактируются отдельно от начального остатка.
- Создание не добавляет financial_action/ledger_leg. Допустимы положительный, нулевой и отрицательный начальные остатки. Balance projection изначально равна opening. Общий остаток включает архивные счета и разделён по валютам; для выбора новых операций возвращаются только активные счета.
- Correction требует `explicitConfirmation: true` и `expectedVersion`. Текущий остаток меняется на точную разницу нового и старого opening. Исторические остатки вычисляются от нового opening и активных текущих revisions. Сами legs, доходы и расходы сохраняются; не создаётся фиктивная финансовая операция. Отдельное предупреждение при создании/увеличении минуса привязано к payload, operation key и актуальным версиям; отмена не пишет данные. Архивный счёт допускает исправление прежних ошибок.
- Все изменения используют общий financialTransaction: session, workspace/membership locks и recheck, account lock, request hash, идемпотентность, версия, audit и projection одним commit. Разрешение archived accounts является внутренней настройкой только management service; обычный executor продолжает запрещать новые операции по архивным счетам.
- Immutable scoped audit сохраняет автора, UTC-время и до/после name/type/currency/opening/balance/description/archive/version. DTO и history ограничены workspace; отсутствуют противоположные стороны переводов, auth secrets или receipts. Queries используют repeatable-read/read-only snapshot. Next.js page — force-dynamic, без shared financial cache; Server Action обновляет страницу при успехе.
- React Hook Form и Zod; русские подписи, pending/error/focus, сохранение dirty input, подтверждения коррекции/архива и отдельное подтверждение минуса. Intl форматирует денежные строки без number conversion, даты — по локали профиля; date-only не сдвигается часовым поясом. Аудит отображает подписанные старые/новые значения.

## Проверенные инварианты

1. Конкурентный create с одним operation key создаёт один счёт; другой payload с прежним ключом даёт conflict. Opening не создаёт доходных/расходных legs. Ноль и минус сохраняются, архивные средства не исчезают, валюты разделены.
2. Valid committed fixtures дохода/расхода из более поздних историй дают текущий остаток; correction сохраняет legs побайтно на уровне DTO, пересчитывает текущий и оба исторических остатка, записывает прежний/новый opening, автора и время. Rename/archive сохраняют историю и средства. Архив не допускает новых операций, исправление opening доступно.
3. Без явного confirmation correction не проходит. Предупреждение минуса откатывает receipt/записи. Подтверждение применяет изменение, stale expectedVersion даёт conflict, токен прежней версии требует нового предупреждения. Ошибка записи audit откатывает account, version и receipt.
4. Чужие workspace/account, отсутствие session и попытка сменить currency запрещены. Family member управляет только общим счётом; после remove запрещены read и receipt retry. Удалённая семья запрещает дальнейшее создание счетов.
5. Browser: пустой список → создание → подготовленные операции → отмена correction → confirmation → correction → rename → archive → сохранённые остатки/история/audit. Отдельно zero/negative, отмена/подтверждение минуса, validation focus и чужой URL. Проверены отсутствие горизонтального overflow и оба viewport/theme. Скриншоты просмотрены; это целевая проверка, не полный аудит WCAG.
6. Локализованное отображение большой суммы сохраняет все значащие цифры и знак без преобразования в number.

Создание доходов/расходов/переводов и показатели целей/резервов/бюджетов/аналитики относятся к следующим фазам. Эта фаза предоставляет корректные opening/current/history значения; не объявляет ещё не реализованные показатели проверенными.
