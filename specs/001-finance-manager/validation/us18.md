# US18 — Недоступность чужих личных финансов (Фаза 17)

Дата: 2026-10-18. Область: T115–T120, ФТ-005,013,025–026,066; КУ-002.

## Реализация

- Единый `requireWorkspace` проверяет UUID до обращения к PostgreSQL. Существующие application services, scoped projections, CSV и financial transaction executor сохраняют актуальную серверную проверку прав; membership и обе стороны перевода проверяются до выдачи receipt при retry. Для последующих P2 transport обязателен тот же guard, а не проверка только в UI.
- Строгий Zod DTO проверки доступа принимает только явный workspaceId. Actor определяется из сессии Better Auth с отключённым cookie cache. Read-only application service и repository используют согласованный snapshot и возвращают только проверенный workspaceId.
- Правило принадлежности строки пространству используется общим `projectLeg`; DTO собирается по разрешённым полям, сохраняет точные денежные строки и не пропускает чужую сторону или дополнительные поля raw records.
- На экранах счетов, бюджета и целей используется общий русскоязычный экран отказа без названий и сумм чужого пространства. Повторная проверка — Server Action с Zod/RHF, состоянием загрузки, безопасными ошибками и переводом focus на сообщение. Успех перезагружает документ, чтобы не переиспользовать старые данные.
- Чтение доступа не является финансовым изменением и не создаёт audit/version/receipt. Все финансовые команды продолжают использовать существующий транзакционный исполнитель, версии и аудит. Новые таблицы и миграции не нужны.

## Проверки

Node.js 24.22.0, pnpm 12.14.0; настоящая отдельная локальная PostgreSQL. Локальные wrappers задают toolchain и тестовое окружение без вывода секретов. SMTP fixture не отправляет реальные письма.

```sh
pnpm test:unit
pnpm test:integration
pnpm exec vitest run --project integration tests/integration/privacy.test.ts
pnpm exec playwright test tests/e2e/privacy.spec.ts tests/e2e/transfers.spec.ts tests/e2e/switching.spec.ts --workers=1
pnpm typecheck
pnpm lint
pnpm format:check
pnpm build
```

- Unit: 87/87, включая 2 US18. Проверены строгий DTO, forged actor/mode, некорректный scope, отказ чужой leg, whitelist projection и no-store.
- PostgreSQL: 92/92, включая 3 US18. Владелец семьи не получает личные счета/историю/аудит, операции, цели, бюджетные итоги и переводы участника. Подмена account id с разрешённым семейным scope запрещена. Прямой auth endpoint не позволяет активировать personal workspace как организацию. CSV возвращает минимальные 401/403 DTO с private,no-store.
- Повторный focused US18: 3/3 после добавления прямых repository account/audit и transfer projections с чужими id. Некорректный UUID в общем guard отклоняется безопасно. После удаления membership чтение, новая команда и retry принятого межпространственного перевода запрещены; баланс принимающей стороны остаётся точной строкой без повторного эффекта.
- Playwright: 8/8 — privacy, transfers, switching в desktop/light и mobile/dark. US18 проверяет два аккаунта в одной семье, прямые personal URLs accounts/budget/goals, CSV, повторную серверную проверку отказа с focus, исключение при открытой форме без потери ввода, отсутствие финансового изменения и anonymous redirect/export. Обе картинки экрана отказа просмотрены: подписи и кнопки читаемы.
- TypeScript, ESLint и Prettier пройдены. Production build успешно завершён; финансовые экраны остаются dynamic. Sandbox запрещал подключение к PostgreSQL и служебный порт PostCSS/Turbopack. Проверки выполнены с разрешением вне sandbox; кеш, сохранивший ошибку сборки, перенесён во временный каталог без удаления.

Первые браузерные прогоны обнаружили ошибки подготовки нового теста: URL фиксировался до завершения навигации, а список участников владельца не обновлялся после принятия приглашения. Исправлены ожидание страницы и повторное чтение списка; итоговый прогон успешен. В существующей switching-регрессии dev-сервер выводил hydration warning и сообщение об оборванном response stream при сетевом отказе; assertions сценария и остальные тесты прошли.
