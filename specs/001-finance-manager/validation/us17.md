# US17 — Переключение пространств (Фаза 16)

Дата: 2026-10-18. Область: T109–T114, ФТ-012–013,063,065; КУ-002,013.

## Реализация

- Общий React Hook Form/Zod переключатель в авторизованном layout показывает активные personal/family пространства и отдельную группу удалённых семей владельца. Финансовые экраны показывают название и тип активного пространства.
- Серверная выборка проверяет session и актуальные полномочия на одном read-only repeatable-read snapshot. Выбор пространства не создаёт финансовую команду и не меняет Better Auth activeOrganizationId. WorkspaceId остаётся явным в URL и каждой финансовой команде.
- Переключение сохраняет раздел accounts/budget/goals, сбрасывает прежние object/period/currency параметры и загружает новый документ: прежние формы, scoped previews и Router cache не используются для нового пространства. Существующие ссылки между пространствами также загружают документ заново.
- Общий реестр несохранённых RHF-форм заменяет повторяющиеся локальные обработчики. Переход по ссылке, смена периода, перезагрузка и переключатель защищены подтверждением. Отмена и ошибка транспорта сохраняют форму; успешный reset снимает dirty-state. Сообщения доступны с клавиатуры и получают focus; загрузка блокирует переключатель.
- Семейный календарь использует пояс семьи независимо от личных поясов участников. Новый семейный пояс первоначально копируется из профиля владельца; владелец может выбрать другой пояс. Изменение существующего пояса переиспользует familyCommand, shared financial executor, expectedVersion, receipt и audit. Исторические financial_date не изменяются. Таблицы и миграции не добавлялись.
- Удалённая семья открывается через существующий history/export интерфейс; повторная серверная проверка не допускает бывших участников и финансовых изменений.

## Проверки

Команды выполнялись на Node.js 24.22.0 и pnpm 12.14.0; PostgreSQL — отдельная локальная тестовая БД. Mail fixture не отправляет реальные письма. Локальные wrappers задавали toolchain и тестовое окружение без вывода секретов.

```sh
pnpm test:unit
pnpm test:integration
pnpm exec vitest run --project integration tests/integration/switching.test.ts tests/integration/family.test.ts
pnpm exec playwright test --workers=1
pnpm typecheck
pnpm lint
pnpm format:check
pnpm build
```

- Unit: 85/85, включая 3 US17. Проверены безопасные маршруты, сброс чужого object/query контекста, family month на границе месяца при разных personal timezone, personal month и контракт предупреждения о потере ввода.
- PostgreSQL: 89/89, включая 3 US17. Новый suite проверяет personal+2families с различающимися счетами, операциями, категориями, бюджетами и целями; точные строки сумм, отсутствие чужих объектов, forged scope/malformed input/no session, отзыв членства, deleted-owner history, общий месяц участников, owner-only timezone, stale version, аудит и неизменность ledger rows после смены пояса. Отдельный regression проверяет наследование пояса владельца. Повторный focused family/switching: 9/9.
- Playwright: 46/46, включая 2 US17 (desktop/light, mobile/dark). US17 проверяет две семьи и personal picker, активный контекст, отмену ухода с dirty input, сетевую ошибку и retry без потери ввода, пустую форму нового пространства, доступ с клавиатуры, отсутствие горизонтального overflow, desktop/light и mobile/dark. Оба screenshot переключателя просмотрены: подписи, формы и переключатель читаемы, горизонтального overflow нет.
- Production build успешно завершён; финансовые страницы остаются dynamic. TypeScript, ESLint и Prettier пройдены.

Первый браузерный прогон обнаружил конфликт пустого status переключателя с существующими status assertions: сообщение скрыто до появления текста, постоянный активный контекст имеет обычную доступную подпись. Повторный прогон был остановлен после обнаружения перезагрузок dev-сервера из-за параллельной production-сборки; итоговый запуск выполнен отдельно от сборки и завершился успешно. Sandbox блокировал PostgreSQL connection и локальный процесс PostCSS/Turbopack; разрешённые проверки выполнялись вне sandbox. Сохранивший ошибку sandbox кеш сборки перенесён во временный каталог без удаления.
