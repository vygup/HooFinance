# US16 — Аналитика по периодам (Фаза 21)

Дата: 2026-10-20. Область: T141–T146, ФТ-049–050, КУ-012–013.

## Реализация

- Динамическая страница `/w/[workspaceId]/analytics` доступна со страницы счетов.
  React Hook Form/Zod поддерживает текущий и прошлый месяцы, текущий год и произвольный
  включительный период. Границы и часовой пояс явно показаны. Ошибки получают focus,
  сетевой сбой сохраняет выбранные даты, повторное чтение безопасно.
- Read-only application service проверяет сессию и актуальные права в общем
  repeatable-read snapshot. Период, операции, категории, счета, бюджет и цели читаются
  в одном снимке. Семейный календарь использует пояс семьи, личный — профиль пользователя.
  Shared financial executor, версии, receipt и audit нужны для изменений; аналитика
  ничего не изменяет и не создаёт искусственных финансовых команд.
- Выбираются только scoped legs активных текущих ревизий. Доходы, расходы, разница,
  категории и дневная динамика вычисляются Decimal на сервере, валюты не смешиваются.
  Переводы и начальные остатки не входят в доходы и расходы. Исправление даты/суммы
  и удаление немедленно отражаются при новом чтении.
- Recharts получает нормализованные безразмерные координаты. Точные суммы остаются
  строками в подсказках и доступных таблицах; React не выполняет денежную арифметику.
  Подписи осей используют цвет темы, анимация отключена. Просмотрен мобильный снимок.
- Месячные бюджетные планы не переписываются: факт ограничен выбранными датами,
  полные месячные планы подписаны отдельно. Существующие счета, цели и резервы
  показывают явно обозначенное текущее состояние независимо от периода. Деньги
  целей не прибавляются к остаткам счетов. Новые таблицы и миграции не создавались.
- Общий переключатель сохраняет раздел аналитики и сбрасывает контекст предыдущего
  пространства. Финансовая страница dynamic, shared cache не добавлен.

## Проверки

Node.js 24.22.0, pnpm 12.14.0 и PostgreSQL 18.6 в изолированных Docker-контейнерах.
Создана отдельная тестовая БД фазы 21 без опубликованных портов. Рабочие данные и внешняя
доставка почты не использовались. Локальные руководства Next.js `use-server` и `page`
прочитаны перед кодом. Shell prerequisites с CRLF запускались через LF-копию без
изменения скриптов проекта.

```sh
pnpm test:unit
pnpm test:integration
pnpm exec vitest run --project unit tests/unit/analytics.test.ts
pnpm exec vitest run --project integration tests/integration/analytics.test.ts
pnpm exec playwright test tests/e2e/analytics.spec.ts --workers=1
pnpm exec playwright test tests/e2e/switching.spec.ts tests/e2e/monthly-budget.spec.ts --workers=1
pnpm typecheck
pnpm lint
pnpm exec prettier --check --end-of-line auto .
pnpm build
git -c core.whitespace=cr-at-eol diff --check
```

- Полный unit-прогон: 100/100. Финальный focused analytics: 4/4.
  Проверены границы месяца/года, високосная дата, строгие DTO, категория 25000,
  разделение валют, исключение переводов, пустой результат и большие точные суммы.
- Полный PostgreSQL-прогон: 110/110; затем расширены проверки семейного календаря
  и добавлен отказ для удалённой семьи. Финальный focused analytics: 3/3.
  Миграции применены на новой тестовой БД. Проверены обе включительные границы,
  текущие ревизии, перенос расхода в прошлый месяц, удаление, общий семейный период
  для разных личных поясов, смена семейного пояса без сдвига финансовых дат,
  бюджет/цель/остаток, разные валюты, отсутствие сессии, чужое пространство,
  неверный интервал, отзыв членства и удалённая семья.
- Playwright analytics: 2/2, desktop/light и mobile/dark. Пустое состояние,
  создание дохода, произвольный однодневный период, график, сетевой отказ,
  сохранение дат, повторное чтение, ошибка периода с focus и отсутствие
  горизонтального переполнения. Финальные снимки сохранены в test-results.
- Браузерные регрессии бюджета и переключения пространств: 4/4.
- TypeScript, ESLint, Prettier и production build пройдены.
  После финальной правки контраста графика повторены TypeScript, ESLint и Playwright.

Исходные тесты ожидаемо падали до появления модулей. При подготовке исправлены fixture
категории (повторное использование id) и ожидание навигации/выбор combobox в Playwright.
Старое тестовое окружение потеряло согласованность реквизитов после перезапуска БД;
проверки выполнены в новой отдельной БД. В dev-сервере при навигации повторяется
ранее зафиксированное сообщение об оборванном response stream; существующие browser
регрессии также показывают hydration warning о caret-color. Итоговые assertions прошли.
