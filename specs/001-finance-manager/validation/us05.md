# US5 — Расходы и категории

Дата: 17.10.2026. Область: Фаза 7, T054–T060, ФТ-019–022, КУ-003.

## Реализация

- Расход принимает strict Zod DTO, активный счёт и категорию expense своего workspace либо создание новой. Положительная decimal-строка, scale валюты и date-only проверяются на сервере без округления ввода. Валюта определяется счётом. Domain использует shared Decimal primitives: 120000 − 3000 = 117000.
- Общий ledger executor блокирует workspace/membership/accounts, проверяет актуальный доступ и обеспечивает атомарные category/audit/action/revision/leg/balance/version/receipt. Repository US4 расширен параметром типа; второй механизм ledger не создавался. Повтор operation key не списывает повторно, другой payload конфликтует. Ошибка аудита откатывает всю операцию.
- Создание или увеличение минуса требует отдельного подтверждения рассчитанного остатка. Предупреждение откатывает транзакцию, включая временно созданную категорию и receipt. Отказ ничего не сохраняет. Token связан с actor, payload, scope и account versions; изменение баланса требует нового предупреждения.
- Category create/update/archive работает для income и expense, требует scope/session и expectedVersion при изменении. Тип существующей категории неизменен. Архив сохраняет FK и суммы истории, но запрещает новые записи. Изменения сохраняют before/after scoped audit и увеличивают version.
- Остатки, история, категории и месячные income/expense читаются одним authorized repeatable-read snapshot. Расходный факт включает только active current revisions; границы месяца start inclusive/end exclusive; валюты и категории учитываются отдельно. Начальный остаток не расход.
- Общая FinancialEntryForm для доходов/расходов: React Hook Form/Zod, русские подписи, focus ошибок и предупреждения, pending, сохранение ввода/ключа после transport failure, dirty navigation guard. Category manager поддерживает оба типа, rename/archive и предупреждение перед архивацией. Финансовые формы недоступны до готовности RHF: исключена ранняя отправка до гидратации. No money arithmetic в React, dynamic route без shared cache. Новых миграций и dependencies нет.

Проверены: единичный эффект конкурентного повтора; конфликт payload; intentional duplicate с новым ключом; отказ чужому workspace/account/category и без session; archived/opposite kind; scale/date/currency rejection; audit rollback; месячные границы и RUB/JPY; decline/confirm/stale и повтор confirmation; категории обоих типов, rename/archive/version conflict и сохранение leg; category fact 3000; family member, отзыв прав запрещает read/retry, deleted family запрещает writes. Browser проверяет пустую/ошибочную форму, 117000, отмену и принятие минуса, rename/archive и отсутствие архивной категории в выборе. Сняты и просмотрены скриншоты обеих тем, mobile проверен на overflow; это целевая a11y проверка, не полный аудит WCAG.

Первый unit запуск ожидаемо падал до создания domain. Подключение PostgreSQL сначала блокировал sandbox, затем БД отсутствовала; запущен изолированный контейнер. Integration обнаружил преждевременное предупреждение до валидации архивной категории: category validation теперь выполняется перед warning, а вся транзакция предупреждения откатывается. Browser первоначально остановился на неверном exact-селекторе label начального остатка; исправлен тест. Общая форма проверена после устранения дублирования. Ранний ввод до hydration обнаружен в финансовых формах и исправлен через RHF readiness. В полном параллельном dev-наборе 23/26 прошли, три прежних сценария family/profile/logout столкнулись с готовностью страниц; для проверки выполнен последовательный прогон. Известное dev сообщение destination stream errored встречалось при browser response abort. Build sandbox запрещал служебный порт Turbopack; кэш сохранён в `/private/tmp`, чистая сборка вне sandbox успешна.
