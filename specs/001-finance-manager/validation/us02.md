# Валидация US2 — Семья и участники

**Дата:** 17.10.2026. **Область:** Фаза 4, T035–T041; ФТ-006–011,014 и КУ-002. **Результат:** пройдено. Последующие истории не реализовывались.

## Реализация

- Создание семьи требует session и operationKey, без предварительного workspace. Organization Plugin создаёт организацию и owner; workspace, audit и receipt сохраняются в той же PostgreSQL-транзакции. Повтор с тем же payload не создаёт вторую семью, изменение payload с прежним ключом даёт conflict. Личное пространство сохраняется.
- Приглашения, принятие/отклонение адресатом, отмена, исключение и выход используют native Organization Plugin на переданном tx. Сохраняются срок 7 суток, ограничения отправки и отмена прежнего секрета при повторной отправке. Регистрация адресата сама по себе не принимает приглашение. Прямые plugin endpoints остаются закрытыми.
- Семейные команды используют общий financial executor: workspace/member locks, повторная проверка доступа, идемпотентность и безопасный результат. Session-only создание и ответы на секретное приглашение используют общий session executor того же модуля, с повторной проверкой сессии на tx. Исключённый участник не получает доступ через прежний receipt.
- `ownership_offer` хранит получателя, инициатора, workspace/version и статус. DB trigger проверяет текущего member при создании предложения. Предложение не меняет владельца. Принятие проверяет получателя, членство и версию; native member rows меняются через доменный tx-aware adapter. Это необходимо для атомарной замены двух ролей: отдельное native изменение роли последнего owner библиотека запрещает. Unique owner index и deferred ownership trigger проверяют целостность commit. Прямое изменение ролей через HTTP запрещено.
- Rename/timezone/confirmed transfer/delete проверяют expectedVersion и увеличивают workspace.version ровно на один. Audit хранит до/после названия, timezone, владельца, версии и статуса удаления. Исключение/выход отменяют ожидающие предложения соответствующему участнику.
- Только единственный оставшийся owner может явно подтвердить soft-delete. Состав семьи повторно проверяется под workspace lock, pending invites/offers отменяются; финансовые записи и личные стороны переводов не меняются. Бывшему владельцу доступны отдельный список удалённых семей, просмотр и CSV.
- `/families` и `/invitations/accept` используют Server Actions, React Hook Form и Zod; доступны русские подписи, loading/error/focus, подтверждения удаления/выхода/исключения и предупреждение о несохранённом вводе. Picker показывает personal и доступные active families; deleted families вынесены отдельно.
- P1 CSV route ограничен сохранённой историей удалённой семьи её бывшему owner. Общий экспорт/импорт остаются US22. CSV: UTF-8 BOM, `;`, CRLF, quoting, multiline, защита формул и исходного апострофа, проверка денежных строк. Межпространственные строки не содержат counterparty account/currency/amount или rate numerator/denominator. Response private, no-store; filename фиксирован.

## Проверенные инварианты

1. Две семьи плюс personal видны только пользователю с доступом; чужое чтение запрещено. Конкурентный create с одинаковым ключом создаёт одну семью.
2. Failure после native organization/member creation откатывает полный createFamily. Failure после замены member roles откатывает owner transfer; предложение остаётся принимаемым после устранения сбоя.
3. Чужая почта, reject/cancel/expired/старый resend secret не создают членство. Member не может rename/invite/delete; owner не может выйти. Remove/leave прекращают доступ, включая retry принятого приглашения.
4. Rename и timezone увеличивают version; stale version и stale offer не меняют данные. Из двух конкурентных ownership accept проходит один. Transfer/remove и invitation accept/delete сериализуются; остаётся ровно один owner.
5. Soft-delete при наличии member запрещён. После удаления нет active picker entry, новых изменений или принятия приглашений; история и экспорт разрешены только бывшему owner.
6. Deleted-family FX fixture сохраняет собственную сумму `100.00 USD`; личные `10000.00 RUB`, account id/name, description, leg id и параметры курса не попадают в CSV. Личный balance projection и leg остаются неизменными. Прямой CSV route возвращает 401/403 без session/прав и private, no-store при успехе.
7. Browser lifecycle: создание → приглашение по письму → регистрация адресата → принятие → owner offer → подтверждение → выход прежнего owner → soft-delete → история → CSV download. Проверены отмена удаления, пустые состояния, focus и отсутствие горизонтального overflow. Скриншоты light desktop/dark mobile просмотрены; это целевая проверка UI, не полный независимый аудит WCAG.
